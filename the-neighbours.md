# The Neighbours

MkDocs is one of several honest ways
to turn text into a documentation
site. The neighbours differ mostly
in what they centre: a language, a
kind of content, a host. None of
them makes your writing better; pick
by fit, and know that moving between
any two is a weekend, not a rewrite
of your life — the Markdown is the
asset, and it travels.

## Hugo

A single fast binary, written in Go,
that builds enormous sites in
seconds and doubles as a general
website engine (blogs, galleries,
whole company sites). Choose it when
the site is bigger than
documentation, or build time is a
real pain. Its cost is a templating
system and conventions of its own
to learn — more power, more machine
room. If Hugo tempts you, note it
needs no Python environment at all.

## Jekyll

The Ruby elder, built into GitHub
Pages itself: push Markdown, Pages
builds it with Jekyll without any
workflow at all. Choose it when the
site must live on Pages with zero
moving parts and modest ambitions.
Slower builds, a smaller extension
story, and a theme shelf that shows
its age — but nearly nothing to
maintain.

## Sphinx

The Python documentation system's
original: reStructuredText (or
Markdown, with effort), and still
the best machinery for API reference
generated from Python code itself —
docstrings in, cross-referenced
reference out. Choose it when the
code's own documentation is the
product. Its learning curve is the
steepest here, and it earns it only
in that one job.

## mdBook

A small Rust tool from the Rust
project's own books: Markdown in, a
clean book-shaped site out, one
binary, almost no configuration.
Choose it for a book — chapters in a
line, read in order. It deliberately
does less than MkDocs: no plugin
menagerie, minimal themes. For a
narrative, that restraint is a
feature.

## Docusaurus

The React-based heavyweight from
Meta: versioned documentation,
translations, blog and docs in one
site, at the price of a Node.js
project with real weight. Choose it
when versions and languages are
requirements today, not someday.
For a handbook, it is a lorry hired
to move a bicycle.

## A wiki (BookStack, Wiki.js, and kin)

The other fork in the road entirely:
pages edited in the browser, stored
in a database, no files, no git.
Choose it when the writers will
never touch a text editor, or when
editing rights and page history must
live in the tool. You trade away
the plain-files virtues this guide
runs on — grep-able, diff-able,
yours — and gain a door anyone can
walk through. Some organisations
should; know which yours is.
